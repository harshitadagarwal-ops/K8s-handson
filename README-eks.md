# Deploy the demo to Amazon EKS (Terraform)

Back to the [project overview](README.md). To run locally instead, see [README-minikube.md](README-minikube.md).

Terraform creates the network, the cluster, the image registry, and the database. Scripts then build the images and deploy the app with the `k8s/overlays/eks` overlay. The database is Amazon RDS for MySQL.

## What gets created

```
                      Internet
                         │
              ┌──────────▼──────────┐
              │  NLB (public subnet)│   created by Kubernetes from the frontend Service
              └──────────┬──────────┘
 VPC 10.0.0.0/16         │
 ┌───────────────────────▼─────────────────────────────┐
 │ private subnets (2 AZs)   EKS managed node group     │
 │   frontend pods ──> backend pods                     │
 │        │ NAT gateway (1) for outbound / ECR pulls    │
 └────────┼────────────────────────────────────────────┘
          │ port 3306, only from the node security group
 ┌────────▼────────────────────────────────────────────┐
 │ database subnets (2 AZs, no route to the internet)   │
 │   RDS MySQL 8.4 (private, encrypted)                 │
 └─────────────────────────────────────────────────────┘
 ECR: <name>/backend, <name>/frontend      Secrets Manager: RDS password
```

| Module | Creates |
|--------|---------|
| `terraform/modules/vpc` | VPC, public / private / database subnets, one NAT gateway, free S3 gateway endpoint |
| `terraform/modules/eks` | EKS cluster, managed node group, KMS key for Secrets encryption, logging |
| `terraform/modules/ecr` | Two private repositories with scanning and lifecycle rules |
| `terraform/modules/rds` | RDS MySQL, security group, generated password in Secrets Manager |

The stack you apply is `terraform/envs/dev`. The optional `terraform/bootstrap` creates an S3 bucket for remote state.

## Security choices

- Nodes run in private subnets. The database sits in isolated subnets with no internet or NAT route.
- The Kubernetes API is public but limited to **your IP**. Terraform refuses `0.0.0.0/0`.
- RDS accepts connections only from the EKS node security group, is not publicly accessible, and is encrypted at rest.
- The database password is generated by RDS and stored in Secrets Manager. It is never in Terraform code, variables, or git. `scripts/deploy-eks` copies it into a Kubernetes Secret through stdin.
- Kubernetes Secrets are envelope-encrypted with a customer-managed KMS key.
- Nodes require IMDSv2 with hop limit 1, so pods cannot read node credentials. Node disks are encrypted gp3.
- ECR tags are immutable and images are scanned on push.
- Control plane audit, API, and authenticator logs are enabled.
- The default VPC security group has no rules.

## Cost choices

- Spot `t3.medium` nodes (set `node_capacity_type = "ON_DEMAND"` on the day of a live demo to avoid interruptions).
- One shared NAT gateway, S3 gateway endpoint, 7-day log retention, ECR keeps only the newest 10 images.
- RDS `db.t4g.micro`, 20 GiB gp3, single-AZ, 1 day of backups.
- Rough running cost is **about $0.20 to $0.25 per hour (about $150 to $180 per month)**. The EKS control plane (about $0.10/h) and the NAT gateway are the largest items. This is an estimate that varies by region and Spot price; check the [AWS Pricing Calculator](https://calculator.aws/). **Destroy the stack when you are done.**

## Prerequisites

- An AWS account and credentials (`aws configure` or SSO) that can create VPC, EKS, IAM, KMS, RDS, ECR, and Secrets Manager resources. A first run with limited permissions fails with `UnauthorizedOperation`; use an admin or a suitably broad role for the demo.
- [Terraform](https://developer.hashicorp.com/terraform/install) 1.10 or newer, [AWS CLI](https://docs.aws.amazon.com/cli/latest/userguide/getting-started-install.html) v2, Docker, kubectl.
- kubectl should be within one minor version of the cluster (default Kubernetes 1.36). Older clients usually work but print warnings.
- For the `.sh` scripts: bash and `python3` (or `python`). On Windows use the `.ps1` scripts instead.

### Install the tools (Windows, once)

```powershell
winget install --id Git.Git -e
winget install --id Hashicorp.Terraform -e
winget install --id Amazon.AWSCLI -e
winget install --id Kubernetes.kubectl -e
winget install --id Docker.DockerDesktop -e
```
Open a **new** terminal afterwards so the new commands are on the PATH. macOS and Linux: use your package manager or the links above. Then check everything is installed:

```powershell
git --version
terraform version          # 1.10 or newer
aws --version              # aws-cli/2.x
kubectl version --client
docker version             # must show BOTH a Client and a Server section (Docker Desktop running)
```
This run used Terraform 1.13.5, AWS CLI 2.34, kubectl 1.32.2 (older than the cluster; it works but prints version-skew warnings), and Docker 28.3.

### Give the AWS CLI credentials (once)

```powershell
aws configure              # Access key ID, secret key, default region (ap-south-1), output format (json)
aws sts get-caller-identity
```
The user needs rights to create VPC, EKS, IAM, KMS, RDS, ECR, and Secrets Manager resources. If your organisation requires MFA or SSO, authenticate that way first (`aws sso login`, or a session token, see [Troubleshooting](#troubleshooting)).

## Quick start: every command in order

Use this once the tools are installed and `aws sts get-caller-identity` shows the right account. The numbered steps below explain each one.

**Windows PowerShell**
```powershell
# 0. get the code and make sure Docker Desktop is running
#    (the repo must contain the terraform/, scripts/ and k8s/overlays/ folders - see the note below)
git clone <your-repo-url> k8s-microservices-app
cd k8s-microservices-app
docker version                                            # Server section must appear; if not, start Docker Desktop and wait

# 1. allow your IP to reach the Kubernetes API
cd terraform\envs\dev
$ip = (Invoke-RestMethod https://checkip.amazonaws.com).Trim()
Set-Content terraform.tfvars "api_allowed_cidrs = [`"$ip/32`"]"

# 2. create VPC, EKS, ECR, RDS (about 15 minutes)
terraform init
terraform plan -out=tfplan
terraform apply tfplan
cd ..\..\..

# 3. build and push images, 4. deploy
.\scripts\build-push-ecr.ps1
.\scripts\deploy-eks.ps1                                  # prints the app URL
```

**Linux / macOS / Git Bash / WSL**
```bash
git clone <your-repo-url> k8s-microservices-app && cd k8s-microservices-app
docker version                                            # Server section must appear

cd terraform/envs/dev
echo "api_allowed_cidrs = [\"$(curl -s https://checkip.amazonaws.com)/32\"]" > terraform.tfvars
terraform init
terraform plan -out=tfplan
terraform apply tfplan
cd ../../..

./scripts/build-push-ecr.sh
./scripts/deploy-eks.sh                                   # prints the app URL
```
Then run the checks in [step 5](#5-open-the-app) and, when finished, the [tear down](#tear-down-do-this-to-stop-the-bill) commands.

> **Before anyone else can clone and repeat this:** the EKS work (the `terraform/` folder, `scripts/`, `k8s/overlays/` and these READMEs) must be committed and pushed to the repository. If it is only on your machine, a fresh clone will contain just the original app. Check with `git status` (nothing should be listed as untracked or modified) and `git log origin/main..HEAD` / `git log github/main..HEAD` (nothing means everything is pushed).

Things that are specific to the run documented here and that you change for yours: the AWS account, the region (`ap-south-1` is the default in `terraform/envs/dev/variables.tf`), your IP in `terraform.tfvars`, the image tag (generated per build), and the load balancer URL (generated per deploy).

## Step-by-step

All commands run from the repo root unless stated otherwise. Docker Desktop must be running before step 3.

### 0. Check your AWS access (takes 10 seconds, saves a failed apply)
```bash
aws sts get-caller-identity                                   # is this the account you intend to use?
aws configure get region                                      # default region for the CLI
aws ec2 describe-availability-zones --region ap-south-1       # must list zones, not "UnauthorizedOperation"
```
If the last command fails with an explicit deny (region or MFA), see the first rows of [Troubleshooting](#troubleshooting) before going further.

### 1. Configure

Linux / macOS / Git Bash:
```bash
cd terraform/envs/dev
cp terraform.tfvars.example terraform.tfvars
curl https://checkip.amazonaws.com        # your public IP
```
Edit `terraform.tfvars` and set `api_allowed_cidrs = ["<that ip>/32"]`.

Windows PowerShell:
```powershell
cd terraform\envs\dev
$ip = (Invoke-RestMethod https://checkip.amazonaws.com).Trim()
Set-Content terraform.tfvars "api_allowed_cidrs = [`"$ip/32`"]"
```
`terraform.tfvars` is gitignored. If your IP changes later (home Wi-Fi, VPN), update it and run `terraform apply` again, otherwise kubectl stops connecting.

### 2. Create the infrastructure (about 15 minutes, mostly EKS and RDS)
```bash
terraform init
terraform plan -out=tfplan        # expect: Plan: 69 to add, 0 to change, 0 to destroy
terraform apply tfplan
cd ../../..                      # back to the repo root for the next steps
```
Applying the saved plan guarantees you create exactly what you reviewed. In the verified run RDS took about 8.5 minutes and the EKS control plane about 10 minutes, in parallel; the node group added about 2 minutes.

### 3. Build and push the images to ECR

Linux / macOS / Git Bash:
```bash
./scripts/build-push-ecr.sh
```
Windows PowerShell (from the repo root):
```powershell
.\scripts\build-push-ecr.ps1
```
Tags are immutable. The script uses the git short SHA (plus a timestamp if you have uncommitted changes) and saves it in `.image-tag`.

### 4. Deploy the app
```bash
./scripts/deploy-eks.sh          # PowerShell: .\scripts\deploy-eks.ps1
```
The script points kubectl at the cluster, creates the namespace, the `app-config` ConfigMap (RDS host) and the `app-secret` Secret (RDS credentials), applies `k8s/overlays/eks` with your ECR image names, waits for the rollout, and prints the load balancer URL.

### 5. Open the app
Open the printed `http://<nlb-hostname>`. **The load balancer DNS name takes about one to two minutes to resolve after the script prints it**; "remote name could not be resolved" during that time is normal, just retry. Add a message; it is stored in RDS.
```bash
kubectl get pods -n demo          # 2 backend + 2 frontend, all 1/1 Running
kubectl get nodes                 # 2 nodes, Ready
kubectl get svc frontend -n demo
kubectl logs deploy/backend -n demo | grep "DB initialized"
```
You will see `Warning: would violate PodSecurity "restricted:latest"` while the script applies the manifests. This is expected: the `demo` namespace enforces the `baseline` profile and only warns about `restricted`, because the containers run as root. It does not block the deployment (see the production upgrades table below).

**Check the whole path from the command line** (frontend, backend, RDS). Windows PowerShell:
```powershell
$lb = kubectl get svc frontend -n demo -o 'jsonpath={.status.loadBalancer.ingress[0].hostname}'
(Invoke-WebRequest "http://$lb" -UseBasicParsing).StatusCode                                  # 200
Invoke-WebRequest "http://$lb/add" -Method Post -Body @{ text = 'hello from eks' } -UseBasicParsing | Out-Null
(Invoke-WebRequest "http://$lb" -UseBasicParsing).Content -match 'hello from eks'              # True
```
Linux / macOS / Git Bash:
```bash
LB=$(kubectl get svc frontend -n demo -o jsonpath='{.status.loadBalancer.ingress[0].hostname}')
curl -s -o /dev/null -w "%{http_code}\n" "http://$LB"                       # 200
curl -s -X POST -d "text=hello from eks" "http://$LB/add" -o /dev/null
curl -s "http://$LB" | grep "hello from eks"
```
If kubectl lists many old clusters (`kubectl config get-contexts`), make sure the current one is yours: `kubectl config use-context arn:aws:eks:ap-south-1:<account-id>:cluster/k8s-demo-dev`. `deploy-eks` already sets this.

### Redeploying after a code change
```bash
./scripts/build-push-ecr.sh && ./scripts/deploy-eks.sh
```

Local state is the default and fine for a solo demo. For a team, run `terraform/bootstrap` (`terraform apply -var bucket_name=<unique-name>`), then follow the comments in `terraform/envs/dev/backend.tf`.

## Live teaching moments

The same commands as on Minikube:

```bash
kubectl delete pod <a-backend-pod-name> -n demo          # self-healing
kubectl scale deployment backend --replicas=4 -n demo    # scaling
kubectl logs deploy/backend -n demo                      # inspecting
kubectl get all -n demo
```
With Spot nodes you can also show what happens when a node is replaced. Use `node_capacity_type = "ON_DEMAND"` if you want a predictable demo.

## Tear down (do this to stop the bill)

```bash
./scripts/destroy-eks.sh          # PowerShell: .\scripts\destroy-eks.ps1
```
The script deletes the `demo` namespace first, which removes the load balancer, then runs `terraform destroy`. **Do not run `terraform destroy` on its own while the app is deployed**: the Kubernetes-created load balancer is not in Terraform state and blocks the VPC from being deleted.

The RDS instance is created without deletion protection and without a final snapshot so the demo can be removed cleanly. For real data set `db_deletion_protection = true` and `db_skip_final_snapshot = false`.

### Confirm nothing is left running (and billing)

After the destroy finishes, each of these should print nothing (replace the region if you changed it):
```powershell
$r = 'ap-south-1'
aws eks list-clusters --region $r --query clusters --output text                                    # no k8s-demo-dev
aws rds describe-db-instances --region $r --query "DBInstances[].DBInstanceIdentifier" --output text   # no k8s-demo-dev-mysql
aws ec2 describe-nat-gateways --region $r --filter Name=state,Values=available --query "NatGateways[].NatGatewayId" --output text
aws elbv2 describe-load-balancers --region $r --query "LoadBalancers[].LoadBalancerName" --output text
aws ecr describe-repositories --region $r --query "repositories[].repositoryName" --output text      # no k8s-demo-dev/*
```
Your account may contain other, unrelated resources that show up in these lists. Only the `k8s-demo-dev` ones belong to this demo. Optional tidy-up of the local kubeconfig: `kubectl config delete-context arn:aws:eks:ap-south-1:<account-id>:cluster/k8s-demo-dev`.

In the documented run the destroy removed all 69 resources with no errors, in roughly 15 to 20 minutes: deleting the namespace and load balancer took about a minute, RDS and the NAT gateway about a minute and a half in parallel, the EKS node group about 8.5 minutes, and the control plane about 4 more. The Kubernetes KMS key is scheduled for deletion rather than removed immediately, which is normal AWS behaviour. If it stops with an error, read it, fix the cause (usually a leftover load balancer, see Troubleshooting), and run `.\scripts\destroy-eks.ps1` again; it is safe to repeat.

## Known limits of this setup (and the production upgrade)

| Demo choice | Production upgrade |
|-------------|--------------------|
| Pods connect to RDS without TLS | Enforce `require_secure_transport` and enable TLS in the app |
| App uses the RDS master user | Create a least-privilege app user |
| DB password copied into a Kubernetes Secret | External Secrets Operator or Secrets Store CSI driver with Pod Identity |
| In-tree Service controller creates the NLB | AWS Load Balancer Controller with an ALB Ingress and TLS (ACM) |
| Load balancer is open to the internet | Restrict with `loadBalancerSourceRanges`, add WAF |
| One NAT gateway, single-AZ RDS | `single_nat_gateway = false`, `db_multi_az = true` |
| Public API endpoint restricted by IP | Private endpoint only, reached through VPN or bastion |
| No NetworkPolicies, containers run as root | NetworkPolicies, non-root `securityContext`, PSA `restricted` |

## Troubleshooting

| Symptom | Check |
|---------|-------|
| `UnauthorizedOperation` "explicit deny ... `Enforce-Single-Region`" | Your AWS account only allows one region and it is not the one in use. Set `region` in `terraform.tfvars` to the allowed region, or ask your admin which one it is. |
| `UnauthorizedOperation` "explicit deny ... `EnforceMFA`" | The credentials are not an MFA session. Get temporary credentials with `aws sts get-session-token --serial-number <mfa-arn> --token-code <code>` (or `aws sso login`), then retry. Do not look for a way around the policy. |
| `terraform plan` fails with another `UnauthorizedOperation` | The AWS identity lacks permissions. Run `aws sts get-caller-identity` to check you are using the account and user you intend. |
| Plan error about `0.0.0.0/0` | Intended. Set `api_allowed_cidrs` to your own `/32`. |
| `kubectl` cannot connect after your IP changes | Update `api_allowed_cidrs` and run `terraform apply`. |
| `kubectl` points at the wrong cluster | `kubectl config get-contexts`, then `aws eks update-kubeconfig --region <region> --name <cluster>`. |
| Backend log shows `DB not ready` | Normal for a short time; the backend retries. If it persists, check `kubectl logs deploy/backend -n demo` and that `app-config` has the RDS host. |
| `ImagePullBackOff` | Run `build-push-ecr` before `deploy-eks`; check `.image-tag` matches a tag in ECR. |
| `error during connect ... pipe/docker_engine` | Docker Desktop is not running. Start it, wait until `docker version` shows a Server section, then rerun `build-push-ecr`. (If you use WSL, the `.sh` scripts also work there once Docker is reachable.) |
| ECR login fails with `400 Bad Request` on Windows PowerShell | Windows PowerShell 5 corrupts the token when it is piped. `build-push-ecr.ps1` already works around this by doing the pipe inside `cmd /c`. If you run the command by hand, run it from `cmd` or PowerShell 7. |
| `kubectl` says the host does not exist | The context points at a deleted cluster. `deploy-eks` switches it for you; manually: `aws eks update-kubeconfig --region ap-south-1 --name k8s-demo-dev`. |
| Browser says the load balancer name cannot be resolved | Wait one to two minutes after the URL is printed. DNS for a new NLB is slow. |
| Push fails with "tag is immutable" | Use a new tag: `IMAGE_TAG=v2 ./scripts/build-push-ecr.sh`. |
| `terraform destroy` hangs on the VPC | A Kubernetes-created load balancer or ENI is left. Use `destroy-eks`, or delete the load balancer in the EC2 console. |
| Spot nodes disappear | Spot interruption. Use `node_capacity_type = "ON_DEMAND"` for live sessions. |
